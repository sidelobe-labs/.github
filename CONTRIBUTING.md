# Contributing

Thanks for taking the time to contribute to a Sidelobe project.

This file provides organization-wide defaults. Repository-specific contribution guidance takes precedence when present.

## Before making a change

For non-trivial public changes, open an issue or start a discussion first so the problem and intended scope are clear.

Keep changes focused. Avoid mixing unrelated refactors, formatting changes and product changes in one pull request.

## Pull requests

A good pull request should:

1. explain what changed and why;
2. stay as small as reasonably possible;
3. include relevant tests or validation steps;
4. update documentation when behaviour or setup changes;
5. avoid committing credentials, private data, generated secrets or local environment files.

Run the repository's documented checks before requesting review.

## Private repositories

Internal repositories may have additional workflow, review or deployment requirements documented in their own README, AGENTS.md or contribution guide.
